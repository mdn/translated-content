{{APIRef("Media Capture and Streams")}}

**`getSettings()`** は {{domxref("MediaStreamTrack")}} インターフェイスのメソッドで、現在の `MediaStreamTrack` の制約可能なプロパティそれぞれの現在の値を含むオブジェクトを返します。

制約されるプロパティの働きの詳細については、[能力と制約と設定](/ja/docs/Web/API/Media_Capture_and_Streams_API/Constraints)を参照してください。

## 構文

```js-nolint
getSettings()
```

### 引数

なし。

### 返値

トラックの制約可能なプロパティの現在の構成を記述するオブジェクトです。

> [!NOTE]
> 返されたオブジェクトは、サイトコードで明示的に設定されたものではなく、プラットフォームのデフォルト値として保有するものも含め、制約されるすべてのプロパティの現在の値を特定します。 代わりに、サイトのコードで指定されたトラックのプロパティに対して、最近設定された制約を取得するには、{{domxref("MediaStreamTrack.getConstraints", "getConstraints()")}} を使用してください。

これらの値は、以前に {{domxref("MediaTrackConstraints")}} オブジェクトを使用して記述し、{{domxref("MediaStreamTrack.applyConstraints", "applyConstraints()")}} を使用して設定した制約に可能な限り一致します。また、制約が変更されていないプロパティや、カスタマイズされた制約が一致しなかったプロパティには、デフォルトの制約が適用されます。これにより、{{domxref("MediaDevices.getUserMedia", "getUserMedia()")}} または {{domxref("MediaStreamTrack.applyConstraints()")}} の呼び出し時に指定したプロパティ値ごとに、制約への準拠としてどの値が選択されたかを確認できます。

ブラウザーが対応していないため、またはコンテキスト上利用できないために、オブジェクトに記載されているプロパティが含まれない場合があります。

例えば、{{Glossary("RTP")}} が WebRTC 接続のネゴシエーション中にこれらの値の一部を提供しないため、{{domxref("RTCPeerConnection")}} に関連付けられたトラックには次の項目が含まれません。

- `deviceId`
- `groupId`
- `echoCancellation`
- `latency`
- `facingMode`

#### すべてのメディアトラックのプロパティ

- `deviceId`
  - : 閲覧セッションに対応するオリジンに対して、対応する {{domxref("MediaStreamTrack")}} のソースを一意に識別する文字列です。この ID は同一オリジンの複数の閲覧セッションで有効であり、ほかのすべてのオリジンとは異なることが保証されるため、複数のセッションで同じソースを使用するようリクエストする際に安全に使用できます。

    同じソースを持つすべてのトラックは、オリジンごとに同じ ID を共有します。そのため、{{domxref("MediaStreamTrack.getCapabilities()")}} は常に `deviceId` に対して値を 1つだけ返します。したがって、{{domxref("MediaStreamTrack.applyConstraints()")}} を呼び出す際に制約を変更する目的にはデバイス ID は利用できません。ただし、{{domxref("MediaDevices.getUserMedia()")}} を呼び出す際の初期のメディア選択には使用できます。

    > [!NOTE]
    > デバイス ID が閲覧セッション全体で同じになるという規則の例外として、プライベートブラウジングモードでは異なる ID が使用され、閲覧セッションごとに変更されます。

    この文字列の実際の値はトラックのソースによって決まり、どのような形式になるかの保証はありません。ただし、仕様では [GUID](https://en.wikipedia.org/wiki/Universally_unique_identifier)<sup>(英語)</sup> を推奨しています。

- `groupId`
  - : {{domxref("MediaStreamTrack")}} のソースを含むデバイスのグループを一意に識別する文字列です。2つのデバイス（`deviceId` で識別される）は、同じ物理デバイスに属している場合、同じグループの一部と見なされます。例えば、スマートフォンに内蔵されたスピーカーとマイクの音声出入力デバイスは、同じ物理デバイスの一部であるため、同じグループ ID を共有します。一方、ヘッドセットのマイクは異なる IDになります。

    この ID は閲覧セッションごとに固有であり、複数の閲覧セッションで使用できません。ただし、{{domxref("MediaDevices.getUserMedia", "getUserMedia()")}} を呼び出す際に、異なるトラックが同じデバイスを使用するかしないかを保証するために使用できます。例えば、入出力に同じヘッドセットを使用する場合です。値を変更できないため、`applyConstraints()` を呼び出す場面では groupId が有用になることはありません。

    この文字列の実際の値はトラックのソースによって決まり、どのような形式になるかの保証はありません。ただし、仕様では GUID を推奨しています。

#### 音声トラックのプロパティ

- `autoGainControl`
  - : 自動ゲイン制御 (AGC) が有効かどうかを指定する論理値です。自動ゲイン制御を使用すると、音源のメディア音量の変化を自動的に管理し、全体の音量レベルを一定に保つことができます。この機能は通常マイクで使用されますが、ほかの入力ソースでも提供できます。
- `channelCount`
  - : トラックに存在する音声チャンネル数を指定する整数です（したがって、各音声フレームに存在する音声サンプル数を示します）。モノラルでは1、ステレオでは2というようになります。
- `echoCancellation`
  - : エコーキャンセルが有効かどうかを指定する論理値です。エコーキャンセルは、ユーザーの入出力デバイス間のクロストークを低減または除去することで、双方向の音声接続でのエコーの影響を防ぐことを試みます。例えば、スピーカーから発せられた音がマイクの生成する入力トラックに含まれるのを防ぐフィルターを適用する場合があります。
- `latency`
  - : 音声の待ち時間を秒単位で指定する浮動小数点数です。待ち時間とは、音声処理の開始から、音声利用処理の次の段階でデータが利用可能になるまでの経過時間です。この値は目標値であり、CPU、伝送、保存のオーバーヘッドなどさまざまな理由により、実際の待ち時間はある程度変動することがあります。
- `noiseSuppression`
  - : ノイズ抑制が有効かどうかを指定する論理値です。ノイズ抑制は、バックグラウンドノイズ、機器のハムノイズなどを除去するために、コードへ渡す前に音声を自動的にフィルタリングします。この機能は通常マイクで使用されますが、ほかの入力ソースでも提供できます。
- `restrictOwnAudio`
  - : 画面キャプチャ中に、キャプチャするタブが発生元のシステム音声をブラウザーが除外しようとするかどうかを指定する論理値です。例えば、キャプチャするウェブページ自体が埋め込み音声や動画を再生している場合、その音声はキャプチャに含まれます。望ましくないエコーが発生したり、ほかのタブやアプリケーションの意図した音声ソースに干渉したりする可能性があるため、キャプチャから除外することが望まれます。処理による音声除去に失敗した場合、ユーザーエージェントはキャプチャするタブが発生元のすべての音声を除外することがあります。

    > [!NOTE]
    > キャプチャする表示面にシステム音声が含まれていない場合、この設定は効果を持ちません。
- `sampleRate`
  - : 音声データのサンプリングレートを 1 秒あたりのサンプル数で指定する整数です。一般的な値には、44,100（標準的な CD 音声）、48,000（標準的なデジタル音声）、96,000（音声マスタリングやポストプロダクションで一般的）、192,000（プロの録音およびマスタリングセッションでの高解像度音声）が含まれます。ただし、帯域幅の要件を減らすために低い値がよく使用されます。8,000サンプル/秒は、完全とは言えないものの理解可能な人間の音声には十分で、11,025 と 22,050 はどちらも、帯域幅が狭く品質を落した音声や音楽でよく使用されます。
- `sampleSize`
  - : 各音声サンプルの線形サイズをビット単位で指定する整数です。最も一般的なサンプルサイズは1サンプルあたり16ビットで、CD 音声などに使用されます。ほかの一般的なサンプルサイズは、帯域幅要件を減らす場合は8、高解像度のプロ用音声の場合は24です。

    トラックの各音声チャンネルには `sampleSize` ビットが必要です。そのため、1サンプルは実際には (`sampleSize` / 8) × `channelCount` バイトのデータになります。例えば、16ビットステレオ音声では、サンプルごとに (16/8)×2、つまり4バイト必要です。
- `suppressLocalAudioPlayback`
  - : タブのキャプチャ時に、タブで再生中の音声をユーザーのローカルスピーカーから停止するかどうかを指定する論理値です。例えば、会議室の外部 AV システムへビデオ通話を配信する場合、ローカルスピーカーではなく AV システムから音声を再生したいはずです。これにより、音声がより大きく明瞭になり、会議の動画とも同期します。
- `volume` {{Deprecated_Inline}} {{Non-standard_Inline}}
  - : トラックの音量レベルを指定する浮動小数点数です。この値は、0.0（無音）から1.0（デバイスが対応する最大音量）の範囲になります。

#### 動画トラックのプロパティ

- `aspectRatio`
  - : 画像の幅（ピクセル単位）を高さ（ピクセル単位）で割った値を指定する浮動小数点数です。小数点以下10桁以上の精度で表されます。一般的な値には、クラシックなテレビの4:3「標準」{{glossary("aspect ratio", "アスペクト比")}}（Apple iPad などのタブレットでも使用）を表す1.3333333333、16:9の高精細ワイドスクリーンアスペクト比を表す1.7777777778、ワイドスクリーンのコンピューターやタブレットで一般的な16:10アスペクト比を表す1.6があります。
- `facingMode`
  - : カメラが向いている方向を指定する文字列です。値は次のいずれかになります。
    - `"user"`
      - : 動画ソースはユーザーに向いています（一般に「セルフィーカメラ」として知られています）。例えば、スマートフォンの前面カメラがこれに含まれます。
    - `"environment"`
      - : 動画ソースはユーザーから離れる方向を向いています。そのため、周囲を映します。スマートフォンの背面カメラです。通常、デバイスで最も高画質のカメラであり、一般的な撮影に使用されます。
    - `"left"`
      - : 動画ソースはユーザーに向きつつ、ユーザーから見て左方向を向いています。例えば、ユーザーを向きながら左肩越しを映すカメラがあります。
    - `"right"`
      - : 動画ソースはユーザーに向きつつ、ユーザーから見て右方向を向いています。例えば、ユーザーを向きながら右肩越しを映すカメラがあります。

    これらは別々のカメラを表す場合もあれば、調整可能なカメラが向けられる方向を表す場合もあります。

- `frameRate`
  - : トラックに含まれる1秒あたりの動画フレーム数を指定する浮動小数点数です。何らかの理由で値を決定できない場合は、ユーザーエージェントが動作しているデバイスの垂直同期レートに一致します。
- `height`
  - : トラックの動画データの高さをピクセル単位で指定する整数です。
- `width`
  - : トラックの動画データの幅をピクセル単位で指定する整数値です。
- `resizeMode`
  - : トラックの解像度を導出するためにユーザーエージェントが使用するモードを指定する文字列です。値は次のいずれかになります。
    - `"none"`
      - : トラックはカメラ、ドライバー、または OS が提供する解像度を使用します。
    - `"crop-and-scale"`
      - : トラックの解像度は、ユーザーエージェントがより高いカメラ解像度からクロップまたは縮小処理を行った結果である場合があります。

#### 共有画面トラックのプロパティ

ユーザーの画面全体またはウィンドウやタブなど画面の一部から共有された動画を含むトラックは、一般的に動画トラックと同じ扱いになりますが、次の設定にも対応します。

- `cursor`
  - : マウスカーソルを生成されたストリームに含めるか、およびどの条件で含めるかを指定する文字列です。可能な値は次のとおりです。
    - `"always"`
      - : マウスがコンテンツ領域の外へ移動しない限り、マウスは常に {{domxref("MediaStream")}} の動画コンテンツに表示されます。
    - `"motion"`
      - : マウスカーソルは移動中、および停止後の短時間は常に動画に含まれます。
    - `"never"`
      - : マウスカーソルは共有動画に含められません。

- `displaySurface`
  - : トラックに含まれるソースの種類を指定する文字列です。値は次のいずれかになります。
    - `"browser"`
      - : ストリームの動画トラックは、{{domxref("MediaDevices.getDisplayMedia","getDisplayMedia()")}} の呼び出し中にユーザーが選択したブラウザータブ1つの内容全体を提示します。
    - `"monitor"`
      - : ストリームの動画トラックは、ユーザーの画面1つ以上の内容全体を提示します。ディスプレイの寸法が異なる場合の空白領域は、ユーザーエージェントが選択した背景で埋められます。
    - `"window"`
      - : ストリームの動画トラックは、ユーザーが選択したウィンドウ1つの内容を提示します。ウィンドウは任意のアプリケーションから選択できます。ユーザーエージェント内のウィンドウだけに限定されません。

    すべてのユーザーエージェントがこれらすべての表示面タイプに対応しているわけではありません。

- `logicalSurface`
  - : キャプチャされる表示領域が論理表示面かどうかを指定する論理値です。論理表示面は画面全体に表示されるとは限らず、ウィンドウのバッキングバッファー（含むウィンドウをスクロールしないとバッファーの一部しか表示されない）や画面外レンダリングコンテキストなど、画面外に存在する場合もあります。可視表示面（つまり、`logicalSurface` が `false` を返す表示面）は、現在画面上に表示されている論理表示面の部分です。

    表示面が論理表示面になる最も一般的なシナリオは、選択された表示面が、画面に一度に表示しきれないほど大きなウィンドウのコンテンツ領域全体を含む場合です。表示面を含むウィンドウをスクロールして残りの内容を表示する必要があるため、その表示面は論理表示面になります。

    例えば、ユーザーエージェントは、ユーザーが文書全体（`true` の `logicalSurface` 値を持つ `browser`）を共有するか、文書の現在表示されている部分（`browser` 表示面の `logicalSurface` は `false`）だけを共有するかを選べるようにすることがあります。

- `screenPixelRatio`
  - : 物理解像度と論理解像度の比率を表す数値です。制約または能力として使用できません。値は、ページのズームが `1.0` でキャプチャ画面の拡大率が `1.0` の場合の1{{glossary("CSS pixel", "CSS ピクセル")}}のサイズを、キャプチャされた[表示面](/ja/docs/Web/API/MediaTrackConstraints/displaySurface)のピクセルの垂直サイズで除算することで計算されます。

    画面に OS を介したズームが適用されることは一般的です。例えば、ディスプレイが高解像度で、標準解像度のディスプレイと同じ物理的なサイズでグラフィックを表示したい場合です。ズームを適用する前の解像度を**論理解像度**、ズームを適用した後の解像度を**物理解像度**と呼びます。

    例えば、

    - キャプチャされる表示面が、物理ピクセル寸法が CSS ピクセル寸法とほぼ同じ標準解像度の画面に表示される場合、`screenPixelRatio` は `1` を返します。
    - キャプチャされる表示面が、高 DPI 解像度の画面に表示され、物理ピクセル寸法が CSS ピクセル寸法の約半分である場合（そのため、1つの CSS ピクセルに4つの物理ピクセルを使用）、`screenPixelRatio` は `2` を返します。

    送信側のキャプチャ画面がズームインされている場合、物理解像度は論理解像度より大きくなります。そのため、ビデオ会議アプリケーションは次の方法で帯域幅と CPU の使用量を減らすことができます。

    1. OS がキャプチャされた表示面に適用したズームを除去します。
    2. 論理解像度で画面キャプチャの動画を送信します。
    3. リモートクライアントで受信した後にズームを再適用し、物理解像度まで拡大します。

    このプロパティにより、[画面キャプチャ API](/ja/docs/Web/API/Screen_Capture_API)を使用するアプリケーションは、画面キャプチャの動画を論理解像度、つまりデバイスに依存しない解像度で送信することでリソースを節約できます。

## 例

### `screenPixelRatio` の基本的な使用

この例では、送信アプリケーションが物理解像度ではなく論理解像度で動画を送信するスケーリング係数のしきい値を表す定数 `RESOLUTION_LIMIT` を定義します。

`screenPixelRatio` がこの上限を超えると、アプリケーションは `screenPixelRatio` の値を使用して物理解像度から論理解像度を計算し、キャプチャした {{domxref("MediaStreamTrack")}} を論理解像度に制約します。

```js
const RESOLUTION_LIMIT = 1.5;

async function startCapture() {
  const stream = await navigator.mediaDevices.getDisplayMedia({
    video: true,
  });
  const track = stream.getVideoTracks()[0];
  const settings = track.getSettings();
  const capabilities = track.getCapabilities();

  if (settings.screenPixelRatio > RESOLUTION_LIMIT) {
    const physicalWidth = capabilities.width.max;
    const physicalHeight = capabilities.height.max;
    const logicalWidth = physicalWidth / settings.screenPixelRatio;
    const logicalHeight = physicalHeight / settings.screenPixelRatio;
    await track.applyConstraints({
      width: logicalWidth,
      height: logicalHeight,
    });
  }
}
```
