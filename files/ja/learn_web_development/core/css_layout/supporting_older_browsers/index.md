ウェブサイトの訪問者には、古いブラウザーを使っている人や、実装した CSS 機能に対応していないブラウザーを使っている人が含まれることがあります。ウェブではよくあることで、CSS には新しい機能が継続的に追加されています。ブラウザーごとに実装の優先順位が異なるため、機能への対応状況にも差があります。この記事では、ウェブ開発者が最新のウェブ技術を利用しながら、古い技術を使うユーザーにもサイトを利用できるようにする方法を説明します。

## サイトのブラウザー利用状況を把握する

ウェブサイトごとに対象ユーザーは異なります。対応方針を決める前に、古いブラウザーでサイトを訪れる人がどのくらいいるかを確認しましょう。既存のウェブサイトに機能を追加したり、既存サイトを置き換えたりする場合は、訪問者が使っている技術を把握できるアクセス解析データを利用できるため、調べるのは簡単です。アクセス解析データがない場合や、新しいサイトを立ち上げる場合は、[Statcounter](https://gs.statcounter.com/) などのサイトで、地域別に絞り込める統計情報を確認できます。

端末の種類や、訪問者がサイトをどのように利用するかも考慮してください。例えば、モバイル端末からの利用が平均より多いサイトもあるでしょう。アクセシビリティや支援技術を使う人への配慮は常に重要ですが、サイトによっては特に重視する必要があります。開発者はユーザーの 1% の利用体験を心配する一方で、それよりはるかに多くいる、アクセシビリティを必要とする人々を見落としがちです。

## 使用したい機能はどの程度対応されているか

{{Compat}}

上の互換性表は、各機能のページの下部にある「ブラウザーの互換性」の節に掲載されています。訪問者が使っているブラウザーを把握したら、利用したい技術が各ブラウザーでどの程度対応されているか、また、その技術を利用できない訪問者にどのくらい簡単に代替手段を提供できるかを評価できます。

MDN では、すべての CSS プロパティページでブラウザー互換性情報を提供しています。表で表示されているこの互換性情報には、主要なブラウザーのリストと、プロパティの対応を開始したバージョンが記載されています。例として、[`flex-flow`](/ja/docs/Web/CSS/Reference/Properties/flex-flow#browser_compatibility) と [`background-color`](/ja/docs/Web/CSS/Reference/Properties/background-color#browser_compatibility) の各ページを参照してください。

これらのブラウザー互換性表では、目的の技術に対応しているブラウザーと、各ブラウザーがその機能に対応し始めたバージョンを確認できます。デスクトップブラウザーとモバイルブラウザーの互換性情報は、別々に表示されます。

機能の対応状況を調べるもう 1 つの一般的な方法は、[Can I Use](https://caniuse.com/) を利用することです。このサイトでは、ウェブプラットフォームの大半の機能について、ブラウザーの対応状況を確認できます。地域別の利用統計も表示できるため、特定の地域に主なユーザーがいるサイトでは役立ちます。Google Analytics アカウントをリンクし、自分のユーザーデータに基づいて分析することもできます。

ユーザーが使っているブラウザーと、そのブラウザーで利用できる技術、そしてサイトで使いたい機能のブラウザー間の対応状況を理解しておけば、適切な判断を下し、すべてのユーザーに最善の方法で対応するための土台になります。

## 機能に対応していても、表示が同じとは限らない

ウェブサイトをすべてのブラウザーで同じように表示することはできません。携帯電話で見る人もいれば、大きなデスクトップ画面で見る人もいます。古いバージョンのブラウザーを使う人もいれば、最新のブラウザーを使う人もいます。スクリーンリーダーでコンテンツを聞く人もいれば、読むためにページを拡大する人もいます。すべての人に対応するには、さまざまな環境を想定してコンテンツを設計する必要があります。最新のブラウザーでは見栄えよく表示しながら、どのような環境からアクセスしても、すべての人が基本的な操作を行えるようにします。

基本的な対応は、ページの通常フローでも意味が通るように、コンテンツを適切に構成することから始まります。データ通信量に制限のあるユーザーのブラウザーでは、画像やフォント、さらには CSS も読み込まれないことがあります。それらが読み込まれなくても、コンテンツにアクセスでき、読みやすい状態にしておきましょう。出発点には、適切に構成された HTML 文書を使います。「スタイルシートを取り除いても、コンテンツの意味は通じるだろうか」と自問してみてください。

ユーザーの環境は多様で、制御できないため、すべての人に同一の利用体験を提供しようと時間を費やしても、商業的なメリットはありません。プレーンな HTML ページと、すべての機能を備えたウェブサイトとの間で、適切なバランスを取る必要があります。CSS を使わない表示をテストすると、サイトの代替表示でもアクセシビリティが保たれているか確認できます。この代替表示を目にするのは、非常に古いブラウザーや機能が制限されたブラウザーのユーザーとは限りません。主な対象ユーザーである最新のブラウザーのユーザーも、ブラウザーやインターネット接続に一時的な問題が起きたときに目にすることがあります。CSS を使えば、このような代替表示を簡単に作成できます。そのため、自分で制御できることに集中し、サイトの[アクセシビリティ](/ja/docs/Web/Accessibility)を高めることに時間を使うのがよいでしょう。そうすれば、より多くのユーザーにサービスを提供できます。

## CSS で代替手段を作成する

CSS 仕様書には、レイアウト方法のような 2 つの類似した機能が同じ要素に適用された場合に、ブラウザーがどう処理するかを説明する情報が含まれています。例えば、要素がフロートされていると同時にグリッドアイテムでもあり、CSS グリッドコンテナーの一部でもある場合の動作を定義しています。また、要素に {{cssxref("margin-top")}} と {{cssxref("margin-block-start")}} の両方のプロパティが設定されている場合の動作も定義しています。

ブラウザーが新しい機能を認識しない場合、その宣言は不正なものとして[エラーを発生させずに](/ja/docs/Web/CSS/Guides/Syntax/Error_handling#css_パーサーのエラー)破棄されます。ブラウザーが対応していない CSS プロパティや値は破棄されるため、古い値と新しい値を同じルールセット内で共存させられます。古い値を新しい値より先に宣言しておけば、新しい値に対応しているブラウザーでは、新しい値が古い値（代替値）を上書きします。

例えば、ほとんどのブラウザーは {{cssxref("display")}} プロパティの 2 値構文に対応しています。対応していないブラウザーでは、古い 1 値構文が使われます。

```css
.container {
  display: inline-flex;
  display: inline flex;
}
```

同様に、この[エラー処理](/ja/docs/Web/CSS/Guides/Syntax/Error_handling#ベンダー接頭辞)によって、古い CSS コードベースは、以前の{{glossary("Vendor_Prefix", "ベンダー接頭辞付き")}}機能に対応しないブラウザーでも動作し続けます。ベンダー接頭辞は現在あまり使われていませんが、接頭辞付きのプロパティや値を含める必要がある場合は、標準の値より前に接頭辞付きの値を宣言してください。そうすれば、標準の値に対応しているブラウザーでは、その値が代替値を上書きします。

### 新しいセレクターの使用

すべてのブラウザーが対応しているわけではない新しいセレクターを使う場合は、より慎重に扱う必要があります。カンマ区切りのセレクターリストに[不正なセレクター](/ja/docs/Learn_web_development/Extensions/Testing/HTML_and_CSS#セレクターの対応)が含まれていると、スタイルブロック全体が無視されます。

ブラウザーがまだ対応していない可能性のある、ベンダー接頭辞付きの[擬似要素](/ja/docs/Web/CSS/Reference/Selectors/Pseudo-elements)や新しい[擬似クラス](/ja/docs/Web/CSS/Reference/Selectors/Pseudo-classes)を使う場合は、{{cssxref(":is", ":is()")}} または {{cssxref(":where", ":where()")}} を使って、接頭辞付きのセレクターを[寛容なセレクターリスト](/ja/docs/Web/CSS/Reference/Selectors/Selector_list#寛容なセレクターリスト)に含めてください。そうすれば、セレクターブロック全体が[無効と判断されて無視される](/ja/docs/Web/CSS/Reference/Selectors/Selector_list#無効なセレクターリスト)のを防げます。

```css
:is(:-prefix-mistake, :unsupported-pseudo),
.valid {
  font-family: sans-serif;
}
:-prefix-mistake,
:unsupported-pseudo,
.valid {
  color: red;
}
```

上記の例では、`.valid` のコンテンツは `sans-serif` になりますが、`red` にはなりません。

## 機能クエリー

機能クエリーを使うと、ブラウザーが特定の CSS 機能に対応しているかどうかをテストできます。まず、その機能に対応していないブラウザー向けの CSS を書き、ブラウザーが対応している場合に、新しい機能を使ったスタイルを追加できます。

次の例では、`subgrid` に対応しているかどうかを機能クエリーでテストし、その対応状況に応じたスタイルを適用します。

```css
* {
  box-sizing: border-box;
}

.wrapper {
  background-color: palegoldenrod;
  padding: 10px;
  max-width: 400px;
  display: grid;
  grid-template-columns: repeat(3, 1fr);
}

.item {
  border-radius: 5px;
  background-color: rgb(207 232 220);
}

@supports (grid-template-rows: subgrid) {
  .wrapper {
    grid-template-rows: subgrid;
    gap: 10px;
    background-color: lightblue;
    text-align: center;
  }
}
```

```html
<div class="wrapper">
  <div class="item">項目 1</div>
  <div class="item">項目 2</div>
  <div class="item">項目 3</div>
  <div class="item">項目 4</div>
  <div class="item">項目 5</div>
  <div class="item">項目 6</div>
</div>
```

機能クエリーは、現行のすべてのブラウザーで対応しています。まず、広く対応されている機能を使った CSS を、機能クエリーの外に記述してください。サイトがすべてのユーザーにとって使いやすく、アクセシビリティも確保できたら、機能クエリーのブロック内に新しい機能を追加します。クエリーした機能に対応しているブラウザーは、そのブロック内の新しい CSS を適用できます。まず幅広く対応されている CSS を記述し、そのうえで、対応している機能に応じて拡張する方法を使いましょう。

## 古いブラウザーでテストする

方法の 1 つは、[テスト](/ja/docs/Learn_web_development/Extensions/Testing)モジュールで説明しているように、Sauce Labs などのオンラインテストツールを使うことです。

## まとめ

古いブラウザー向けに代替 CSS を用意し、新機能を安心してテストする方法を学びました。これから登場する新しい技術も、自信を持って活用できるでしょう。

CSS レイアウトに関する記事を読み終えたら、このモジュールの理解度を[基本的なレイアウトの理解度](/ja/docs/Learn_web_development/Core/CSS_layout/Fundamental_Layout_Comprehension)で確認しましょう。
