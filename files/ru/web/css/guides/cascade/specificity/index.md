**Специфичность** — это вес, который браузеры используют в алгоритме каскада, чтобы определить, какое [CSS-объявление](/ru/docs/Learn_web_development/Core/Styling_basics/What_is_CSS) наиболее подходит элементу и, следовательно, какое значение свойства будет к нему применено. Алгоритм специфичности вычисляет этот вес по [CSS-селектору](/ru/docs/Web/CSS/Reference#селекторы) и сравнивает полученные значения, чтобы решить, какое из конкурирующих CSS-объявлений в пределах одного источника и слоя будет применено к элементу.

> [!NOTE]
> Браузеры учитывают специфичность **после** того, как определены [источник каскада и важность](/ru/docs/Web/CSS/Guides/Cascade/Introduction). Иными словами, для конкурирующих объявлений свойства специфичность имеет значение и сравнивается только между селекторами из того [источника и слоя каскада](/ru/docs/Web/CSS/Reference/At-rules/@layer), который имеет приоритет для этого свойства. [Близость области видимости](/ru/docs/Web/CSS/Reference/At-rules/@scope#how_scope_conflicts_are_resolved) и порядок следования начинают играть роль, когда специфичности селекторов конкурирующих объявлений в приоритетном слое каскада равны.

## Как вычисляется специфичность?

Специфичность — это вес, придаваемый конкретному CSS-объявлению. Алгоритм специфичности вычисляет этот вес по количеству [селекторов каждой весовой категории](#весовые_категории_селекторов) в селекторе, который соответствует элементу (или псевдоэлементу). Если для одного и того же элемента есть два или более объявления с разными значениями свойства, применяется значение из блока стилей, у которого подходящий селектор имеет наибольший вес.

По сути, специфичность — это значение из трёх столбцов, соответствующих трём категориям, или весам, — ID, CLASS и TYPE, — по числу типов селекторов. Значение отражает количество компонентов селектора в каждой весовой категории и записывается как _ID - CLASS - TYPE_. Три столбца получаются подсчётом компонентов каждой весовой категории в селекторах, которые соответствуют элементу.

### Весовые категории селекторов

Весовые категории селекторов перечислены здесь в порядке убывания специфичности:

- Столбец ID
  - : Включает только [селекторы идентификаторов](/ru/docs/Web/CSS/Reference/Selectors/ID_selectors), например `#example`. Каждый идентификатор в подходящем селекторе добавляет к весу 1-0-0.
- Столбец CLASS
  - : Включает [селекторы классов](/ru/docs/Web/CSS/Reference/Selectors/Class_selectors), например `.myClass`, селекторы атрибутов, такие как `[type="radio"]` и `[lang|="fr"]`, и псевдоклассы, например `:hover`, `:nth-of-type(3n)` и `:required`. Каждый класс, селектор атрибута или псевдокласс в подходящем селекторе добавляет к весу 0-1-0.
- Столбец TYPE
  - : Включает [селекторы типов](/ru/docs/Web/CSS/Reference/Selectors/Type_selectors), например `p`, `h1` и `td`, и псевдоэлементы, такие как `::before`, `::placeholder`, и все остальные селекторы с двойным двоеточием. Каждый тип или псевдоэлемент в подходящем селекторе добавляет к весу 0-0-1.
- Без значения
  - : Универсальный селектор ({{CSSxRef("Universal_selectors", "*")}}), а также псевдокласс {{cssxref(":where()")}} и его параметры не учитываются при вычислении веса, поэтому их значение равно 0-0-0, но элементам они соответствуют. Эти селекторы не влияют на вес специфичности.

Комбинаторы, такие как {{CSSxRef("Next-sibling_combinator", "+")}}, {{CSSxRef("Child_combinator", "&gt;")}}, {{CSSxRef("Subsequent-sibling_combinator", "~")}}, [" "](/ru/docs/Web/CSS/Reference/Selectors/Descendant_combinator) и {{CSSxRef("Column_combinator", "||")}}, могут сделать селектор точнее в том, что он выбирает, но к весу специфичности ничего не добавляют.

Комбинатор вложенности `&` не добавляет веса специфичности, а вложенные правила — добавляют. С точки зрения специфичности и функциональности вложенность очень похожа на псевдокласс {{cssxref(":is()")}}.

Как и вложенность, псевдоклассы {{cssxref(":is()")}}, {{cssxref(":has()")}} и отрицание ({{cssxref(":not()")}}) сами по себе веса не добавляют. Однако их параметры — добавляют. Вес специфичности каждого из них берётся из того селектора-параметра в списке, у которого специфичность наибольшая. Аналогично для вложенных селекторов: вес, добавляемый вложенным компонентом, — это вес селектора с наибольшей специфичностью из списка вложенных селекторов через запятую.

[Исключения для `:not()`, `:is()`, `:has()` и вложенности CSS](#исключения_для_is_not_has_и_вложенности_css) рассматриваются ниже.

#### Подходящий селектор

Вес специфичности берётся из подходящего селектора. Возьмём для примера такой CSS-селектор из трёх селекторов через запятую:

```css
[type="password"],
input:focus,
:root #myApp input:required {
  color: blue;
}
```

Селектор `[type="password"]` из этого списка с весом специфичности `0-1-0` применяет объявление `color: blue` ко всем полям ввода пароля.

Любые поля ввода, независимо от типа, при получении фокуса соответствуют второму селектору в списке, `input:focus`, с весом специфичности `0-1-1`: этот вес складывается из псевдокласса `:focus` (0-1-0) и типа `input` (0-0-1). Если поле пароля в фокусе, оно соответствует `input:focus`, и вес специфичности объявления `color: blue` будет `0-1-1`. Когда фокуса нет, вес остаётся `0-1-0`.

Специфичность обязательного поля ввода, вложенного в элемент с атрибутом `id="myApp"`, равна `1-2-1`: один идентификатор, два псевдокласса и один тип элемента.

Если поле пароля с атрибутом `required` вложено в элемент с `id="myApp"`, вес специфичности будет `1-2-1` — один идентификатор, два псевдокласса и один тип элемента, — независимо от того, в фокусе оно или нет. Почему в этом случае вес `1-2-1`, а не `0-1-1` или `0-1-0`? Потому что вес специфичности берётся из подходящего селектора с наибольшим весом. Вес определяется сравнением значений в трёх столбцах слева направо.

```css
[type="password"] {
  /* 0-1-0 */
}
input:focus {
  /* 0-1-1 */
}
:root #myApp input:required {
  /* 1-2-1 */
}
```

### Сравнение по трём столбцам

Когда значения специфичности нужных селекторов определены, количество компонентов в каждом столбце сравнивается слева направо.

```css
#myElement {
  color: green; /* 1-0-0  — ПОБЕЖДАЕТ!! */
}
.bodyClass .sectionClass .parentClass [id="myElement"] {
  color: yellow; /* 0-4-0 */
}
```

Первый столбец — это значение компонента _ID_, то есть количество идентификаторов в каждом селекторе. Сначала сравниваются числа в столбцах _ID_ конкурирующих селекторов. Селектор с бо́льшим значением в столбце _ID_ побеждает, какими бы ни были значения в остальных столбцах. В примере выше у жёлтого селектора в сумме больше компонентов, но значение имеет только первый столбец, поэтому текст будет зелёным.

Если числа в столбцах _ID_ конкурирующих селекторов равны, сравнивается следующий столбец, _CLASS_, как показано ниже.

```css
#myElement {
  color: yellow; /* 1-0-0 */
}
#myApp [id="myElement"] {
  color: green; /* 1-1-0  — ПОБЕЖДАЕТ!! */
}
```

Столбец _CLASS_ — это количество имён классов, селекторов атрибутов и псевдоклассов в селекторе. Когда значения в столбце _ID_ равны, побеждает селектор с бо́льшим значением в столбце _CLASS_, независимо от значения в столбце _TYPE_. Это показано в примере ниже.

```css
:root input {
  color: green; /* 0-1-1 — ПОБЕЖДАЕТ, потому что в столбце CLASS больше */
}
html body main input {
  color: yellow; /* 0-0-4 */
}
```

Если числа в столбцах _CLASS_ и _ID_ конкурирующих селекторов совпадают, в дело вступает столбец _TYPE_. Столбец _TYPE_ — это количество типов элементов и псевдоэлементов в селекторе. Когда значения в первых двух столбцах равны, побеждает селектор с бо́льшим числом в столбце _TYPE_.

Если у конкурирующих селекторов одинаковые значения во всех трёх столбцах, действует правило близости: приоритет получает стиль, объявленный последним.

```css
input.myClass {
  color: yellow; /* 0-1-1 */
}
:root input {
  color: green; /* 0-1-1 ПОБЕЖДАЕТ, потому что объявлен позже */
}
```

### Исключения для `:is()`, `:not()`, `:has()` и вложенности CSS

Псевдокласс совпадения с любым из списка {{cssxref(":is()")}}, реляционный псевдокласс {{cssxref(":has()")}} и псевдокласс отрицания {{cssxref(":not()")}} при вычислении веса специфичности _не_ считаются псевдоклассами. Сами по себе они ничего не добавляют к специфичности. Однако селекторы-параметры, переданные в скобках, участвуют в алгоритме специфичности: вес этих псевдоклассов при вычислении специфичности равен [весу](#весовые_категории_селекторов) их параметра.

```css
p {
  /* 0-0-1 */
}
:is(p) {
  /* 0-0-1 */
}

h2:nth-last-of-type(n + 2) {
  /* 0-1-1 */
}
h2:has(~ h2) {
  /* 0-0-2 */
}

div.outer p {
  /* 0-1-2 */
}
div:not(.inner) p {
  /* 0-1-2 */
}
```

Обратите внимание, что в парах селекторов выше вес специфичности, который дают псевдоклассы `:is()`, `:has()` и `:not()`, — это вес селектора-параметра, а не самого псевдокласса.

Все три псевдокласса принимают в качестве параметра сложный список селекторов через запятую. Этим можно воспользоваться, чтобы повысить специфичность селектора:

```css
:is(p, #fakeId) {
  /* 1-0-0 */
}
h1:has(+ h2, > #fakeId) {
  /* 1-0-1 */
}
p:not(#fakeId) {
  /* 1-0-1 */
}
div:not(.inner, #fakeId) p {
  /* 1-0-2 */
}
```

В блоке кода выше в селекторы добавлен `#fakeId`. Этот `#fakeId` добавляет `1-0-0` к весу специфичности каждого абзаца.

Сложные списки селекторов при [вложенности CSS](/ru/docs/Web/CSS/Guides/Nesting) ведут себя точно так же, как псевдокласс `:is()`.

```css
p,
#fakeId {
  span {
    /* 1-0-1 */
  }
}
```

В блоке кода выше для сложного селектора `p, #fakeId` специфичность берётся из `#fakeId` и `span`, поэтому и у `p span`, и у `#fakeId span` она равна `1-0-1`. Это та же специфичность, что и у селектора `:is(p, #fakeId) span`.

Как правило, специфичность стоит держать как можно ниже, но если по какой-то причине нужно её повысить, эти три псевдокласса могут помочь.

```css
a:not(#fakeId#fakeId#fakeID) {
  color: blue; /* 3-0-1 */
}
```

В этом примере все ссылки будут синими, если только их не переопределит объявление для ссылок с тремя или более идентификаторами, значение цвета для `a` с [флагом `!important`](#исключение_!important) или [встроенный стиль](#встроенные_стили) с цветом у самой ссылки. Если используете такой приём, добавьте комментарий, объясняющий, зачем понадобился этот хак.

### Встроенные стили

Встроенные стили, добавленные к элементу (например, `style="font-weight: bold;"`), всегда переопределяют любые обычные стили из авторских таблиц стилей, поэтому можно считать, что у них наивысшая специфичность. Можно представлять себе, что вес специфичности встроенных стилей равен `1-0-0-0`.

Переопределить встроенные стили можно только с помощью `!important`.

Многие JavaScript-фреймворки и библиотеки добавляют встроенные стили. Один из способов переопределить их — использовать `!important` с очень точным селектором, например селектором атрибута по встроенному стилю.

```html
<p style="color: purple">…</p>
```

```css
p[style*="purple"] {
  color: rebeccapurple !important;
}
```

Обязательно добавляйте комментарий к каждому использованию флага `!important`, чтобы тем, кто будет поддерживать код, было понятно, почему применён этот антипаттерн CSS.

### Исключение `!important`

CSS-объявления, помеченные как важные, переопределяют любые другие объявления в пределах того же слоя каскада и источника. Хотя технически [`!important`](/ru/docs/Web/CSS/Reference/Values/important) не имеет отношения к специфичности, он напрямую взаимодействует и со специфичностью, и с каскадом. Он меняет порядок [каскада](/ru/docs/Web/CSS/Guides/Cascade/Introduction) таблиц стилей на обратный.

Если конфликтуют объявления из одного источника и слоя каскада и у одного из значений свойства установлен флаг `!important`, применяется важное объявление, независимо от специфичности. Если к одному элементу применяются конфликтующие объявления из одного источника и слоя каскада, и все они с флагом `!important`, применяется объявление с большей специфичностью.

Использование `!important` для переопределения специфичности считается **плохой практикой**, и для этой цели его следует избегать. Понимание специфичности и каскада и умение ими пользоваться позволяют обойтись без флага `!important`.

Вместо того чтобы переопределять сторонний CSS (из внешних библиотек, таких как Bootstrap или normalize.css) с помощью `!important`, импортируйте сторонние стили прямо в [слои каскада](/ru/docs/Web/CSS/Reference/At-rules/@layer). Если без `!important` в вашем CSS не обойтись, прокомментируйте его использование, чтобы те, кто будет поддерживать код, знали, почему объявление помечено как важное, и не переопределяли его. И уж точно не используйте `!important` при написании плагинов или фреймворков, которые другие разработчики будут подключать, не имея возможности их контролировать.

### Исключение `:where()`

У псевдокласса корректировки специфичности {{cssxref(":where()")}} специфичность всегда заменяется нулём, `0-0-0`. Он позволяет сделать CSS-селектор очень точным в выборе элемента, не повышая специфичности.

Когда вы пишете сторонний CSS для разработчиков, у которых не будет возможности его редактировать, хорошей практикой считается делать специфичность как можно ниже. Например, если ваша тема содержит такой CSS:

```css
:where(#defaultTheme) a {
  /* 0-0-1 */
  color: red;
}
```

То разработчик, подключающий виджет, может легко переопределить цвет ссылок, используя только селекторы типов.

```css
footer a {
  /* 0-0-2 */
  color: blue;
}
```

### Как блоки `@scope` влияют на специфичность

Размещение набора правил внутри блока {{cssxref("@scope")}} не влияет на специфичность его селектора, какие бы селекторы ни использовались в [корне и границе области](/ru/docs/Web/CSS/Reference/At-rules/@scope#syntax).
Однако если вы явно добавите псевдокласс {{cssxref(":scope")}}, его нужно учитывать при вычислении специфичности.
У `:scope`, как и у всех обычных псевдоклассов, специфичность равна 0-1-0. Например:

```css
@scope (.article-body) {
  /* у :scope img специфичность 0-1-0 + 0-0-1 = 0-1-1 */
  :scope img {
  }
}
```

Подробнее см. в разделе [Specificity in `@scope`](/ru/docs/Web/CSS/Reference/At-rules/@scope#specificity_in_scope).

## Советы, как избежать проблем со специфичностью

Вместо `!important` используйте слои каскада и низкую специфичность во всём CSS, чтобы стили легко переопределялись чуть более специфичными правилами. Семантический HTML даёт опорные точки, от которых удобно применять стили.

### Как сделать селектор точнее, повышая или не повышая специфичность

Если перед выбираемым элементом указать раздел документа, который вы стилизуете, правило становится точнее. В зависимости от того, как это сделать, можно добавить немного специфичности, много или совсем не добавлять, как показано ниже:

```html
<main id="myContent">
  <h1>Text</h1>
</main>
```

```css
#myContent h1 {
  color: green; /* 1-0-1 */
}
[id="myContent"] h1 {
  color: yellow; /* 0-1-1 */
}
:where(#myContent) h1 {
  color: blue; /* 0-0-1 */
}
```

Независимо от порядка правил, заголовок будет зелёным, потому что это правило самое специфичное.

#### Снижение специфичности идентификатора

Специфичность зависит от формы селектора. Указать `id` элемента в селекторе атрибута, а не в селекторе идентификатора, — хороший способ сделать селектор точнее, не добавляя чрезмерной специфичности. В предыдущем примере селектор `[id="myContent"]` при вычислении специфичности считается селектором атрибута, хотя и выбирает элемент по идентификатору.

Если нужно сделать селектор точнее, но совсем не добавлять специфичности, можно также передать `id` или любую часть селектора в качестве параметра в псевдокласс корректировки специфичности `:where()`.

### Повышение специфичности повторением селектора

В качестве особого способа повысить специфичность можно повторять веса из столбцов _CLASS_ или _ID_. Повторение селекторов идентификатора, класса, псевдокласса или атрибута внутри составного селектора повышает специфичность — это помогает, когда нужно переопределить очень специфичные селекторы, которые вы не контролируете.

```css
#myId#myId#myId span {
  /* 3-0-1 */
}
.myClass.myClass.myClass span {
  /* 0-3-1 */
}
```

Пользуйтесь этим как можно реже или не пользуйтесь вовсе. Если всё же повторяете селекторы, всегда комментируйте такой CSS.

С помощью `:is()` и `:not()` (а также `:has()`) можно повысить специфичность, даже если нельзя добавить `id` родительскому элементу:

```css
:not(#fakeID#fakeId#fakeID) span {
  /* 3-0-1 */
}
:is(#fakeID#fakeId#fakeID, span) {
  /* 3-0-0 */
}
```

### Приоритет над сторонним CSS

Стандартный способ сделать так, чтобы один набор стилей имел приоритет над другим, — слои каскада, и им для этого не нужна специфичность! Обычные (не важные) авторские стили, импортированные в слои каскада, имеют более низкий приоритет, чем авторские стили вне слоёв.

Если стили берутся из таблицы стилей, которую вы не можете отредактировать или не понимаете, а переопределить их нужно, можно импортировать неподконтрольные вам стили в слой каскада. Стили в слоях, объявленных позже, имеют приоритет, а стили вне слоёв имеют приоритет над всеми стилями в слоях из того же источника.

Когда элементу соответствуют два селектора из разных слоёв, решают источник и важность; специфичность селектора в проигравшей таблице стилей значения не имеет.

```css
@import "TW.css" layer();
p,
p * {
  font-size: 1rem;
}
```

В примере выше весь текст абзацев, включая вложенное содержимое, будет размером `1rem`, сколько бы у абзацев ни было классов, соответствующих таблице стилей TW.

### Как избежать `!important` и переопределить его

Лучший подход — не использовать `!important` вовсе. Объяснения про специфичность выше должны помочь обойтись без этого флага и убрать его там, где он встретится.

Чтобы избавиться от кажущейся необходимости в `!important`, можно сделать одно из следующего:

- Повысить специфичность селектора объявления, которое раньше было `!important`, так, чтобы она была выше, чем у других объявлений
- Дать ему такую же специфичность и разместить после объявления, которое нужно переопределить
- Снизить специфичность селектора, который вы пытаетесь переопределить.

Все эти способы описаны в предыдущих разделах.

Если убрать флаги `!important` из чужой таблицы стилей нельзя, переопределить важные стили можно только с помощью `!important`. Отличное решение — создать [слой каскада](/ru/docs/Web/CSS/Reference/At-rules/@layer) с переопределениями важных объявлений. Это можно сделать двумя способами:

#### Способ 1

1. Создайте отдельную короткую таблицу стилей, которая содержит только важные объявления, переопределяющие те важные объявления, которые вы не смогли убрать.
2. Импортируйте эту таблицу стилей первой в вашем CSS с помощью `layer()`, разместив инструкцию `@import` до подключения других таблиц стилей. Так важные переопределения будут импортированы первым слоем.

```css
@import "importantOverrides.css" layer();
```

#### Способ 2

1. В начале объявлений таблицы стилей создайте именованный слой каскада:

   ```css
   @layer importantOverrides;
   ```

2. Каждый раз, когда нужно переопределить важное объявление, объявляйте его внутри этого именованного слоя. Объявляйте в нём только важные правила.

   ```css
   [id="myElement"] p {
     /* здесь обычные стили */
   }
   @layer importantOverrides {
     [id="myElement"] p {
       /* здесь важный стиль */
     }
   }
   ```

Специфичность селектора важного стиля внутри слоя может быть низкой — лишь бы он соответствовал элементу, стиль которого нужно переопределить. Обычные стили следует объявлять вне слоя, потому что стили в слоях имеют более низкий приоритет, чем стили вне слоёв.

### Независимость от близости в дереве

Близость элемента к другим элементам, указанным в селекторе, не влияет на специфичность.

```css
body h1 {
  color: green;
}

html h1 {
  color: purple;
}
```

Элементы `<h1>` будут фиолетовыми, потому что при одинаковой специфичности приоритет имеет селектор, объявленный последним.

### Непосредственно выбранные элементы и унаследованные стили

Стили, заданные непосредственно для элемента, всегда имеют приоритет над унаследованными стилями, независимо от специфичности унаследованного правила. Возьмём такие CSS и HTML:

```css
#parent {
  color: green;
}

h1 {
  color: purple;
}
```

```html
<html lang="ru">
  <body id="parent">
    <h1>Вот заголовок!</h1>
  </body>
</html>
```

Заголовок `h1` будет фиолетовым, потому что селектор `h1` выбирает именно этот элемент, а зелёный цвет лишь унаследован из объявлений `#parent`.

## Примеры

В следующем CSS три селектора задают цвет элементам {{HTMLElement('input')}}. Для конкретного поля ввода вес специфичности объявления цвета, имеющего приоритет, — это вес подходящего селектора с наибольшим весом:

```css
#myElement input.myClass {
  color: red;
} /* 1-1-1 */
input[type="password"]:required {
  color: blue;
} /* 0-2-1 */
html body main input {
  color: green;
} /* 0-0-4 */
```

Если все эти селекторы выбирают одно и то же поле ввода, оно будет красным, потому что у первого объявления наибольшее значение в столбце _ID_.

У последнего селектора четыре компонента _TYPE_. Хотя численно его значение самое большое, сколько бы элементов и псевдоэлементов в нём ни было, даже 150, компоненты _TYPE_ никогда не имеют приоритета над компонентами _CLASS_. Значения столбцов сравниваются слева направо, и к следующему столбцу переходят, только если значения равны.

Если бы в примере выше мы заменили селектор идентификатора селектором атрибута, у первых двух селекторов была бы одинаковая специфичность:

```css
[id="myElement"] input.myClass {
  color: red;
} /* 0-2-1 */
input[type="password"]:required {
  color: blue;
} /* 0-2-1 */
```

Когда у нескольких объявлений одинаковая специфичность, к элементу применяется последнее найденное в CSS объявление. Если оба селектора соответствуют одному и тому же {{HTMLElement('input')}}, цвет будет синим.

## Дополнительные замечания

Несколько моментов о специфичности, которые стоит помнить:

1. Специфичность применяется, только когда один и тот же элемент выбирается несколькими объявлениями в одном слое каскада или источнике. Специфичность имеет значение только для объявлений одинаковой важности из одного источника и [слоя каскада](/ru/docs/Web/CSS/Reference/At-rules/@layer). Если подходящие селекторы относятся к разным источникам, какое объявление имеет приоритет, определяет [каскад](/ru/docs/Web/CSS/Guides/Cascade/Introduction).

2. Если у двух селекторов в одном слое каскада и источнике одинаковая специфичность, затем вычисляется близость области видимости: побеждает набор правил с наименьшей близостью. Подробности и пример см. в разделе [How `@scope` conflicts are resolved](/ru/docs/Web/CSS/Reference/At-rules/@scope#how_scope_conflicts_are_resolved).

3. Если близость области видимости у обоих селекторов тоже одинакова, в дело вступает порядок в исходном коде. При прочих равных побеждает последний селектор.

4. Согласно правилам CSS, стили [непосредственно выбранных элементов](#непосредственно_выбранные_элементы_и_унаследованные_стили) всегда имеют приоритет над правилами, которые элемент наследует от предка.

5. [Близость элементов](#независимость_от_близости_в_дереве) в дереве документа не влияет на специфичность.
