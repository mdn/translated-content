Контейнерные запросы позволяют применять стили к элементу в зависимости от определённых характеристик его контейнера, а именно от:

- имени контейнера ({{cssxref("container-name")}});
- размера контейнера;
- стилей, применённых к контейнеру;
- состояния прокрутки (scroll-state) контейнера или его прокручиваемого предка;
- того, позиционирован ли контейнер [относительно якоря](/ru/docs/Web/CSS/Guides/Anchor_positioning) и применён ли к нему [запасной вариант position-try](/ru/docs/Web/CSS/Guides/Anchor_positioning/Try_options_hiding).

Контейнерные запросы — альтернатива [медиазапросам](/ru/docs/Web/CSS/Guides/Media_queries), которые применяют стили к элементам в зависимости от размера области просмотра или других характеристик устройства.

Эта статья знакомит с использованием контейнерных запросов, в первую очередь — запросов к размеру контейнера. Запросы [к стилю](/ru/docs/Web/CSS/Guides/Containment/Container_size_and_style_queries#container_style_queries), [к состоянию прокрутки](/ru/docs/Web/CSS/Guides/Conditional_rules/Container_scroll-state_queries) и [запросы к контейнерам, позиционированным относительно якоря](/ru/docs/Web/CSS/Guides/Anchor_positioning/Anchored_container_queries) подробно разобраны в отдельных руководствах.

## Использование запросов к размеру контейнера

Если контейнерные запросы в целом применяют стили в зависимости от имени или типа контейнера, то запросы к размеру контейнера применяют стили именно в зависимости от его размеров. Чтобы использовать запросы к размеру контейнера, нужно объявить на элементе [контекст изоляции](#именование_контекстов_изоляции) — так браузер будет знать, что позже вы можете запросить размеры этого контейнера.
Для этого используйте свойство {{cssxref("container-type")}} со значением `size`, `inline-size` или `normal`.

Эти значения действуют так:

- `size`
  - : Запрос будет основан на [строчном и блочном](/ru/docs/Web/CSS/Guides/Logical_properties_and_values/Basic_concepts#block_and_inline_dimensions) размерах контейнера.
    К контейнеру применяется изоляция ([containment](/ru/docs/Web/CSS/Guides/Containment/Using)) макета, стиля и размера.
- `inline-size`
  - : Запрос будет основан на [строчном](/ru/docs/Web/CSS/Guides/Logical_properties_and_values/Basic_concepts#block_and_inline_dimensions) размере контейнера.
    К элементу применяется изоляция макета, стиля и строчного размера.
- `normal`
  - : Значение по умолчанию. Элемент не является контейнером ни для каких запросов к размеру, но всё ещё может быть контейнером для [запросов только по имени](#запросы_только_по_имени_контейнера) и запросов к стилю контейнера.

Рассмотрим пример компонента карточки для записи в блоге с заголовком и текстом:

```html
<div class="post">
  <div class="card">
    <h2>Заголовок карточки</h2>
    <p>Содержимое карточки</p>
  </div>
</div>
```

Контекст изоляции можно создать с помощью свойства `container-type`:

```css
.post {
  container-type: inline-size;
}
```

Затем с помощью @-правила {{cssxref("@container")}} определите контейнерный запрос.
Запрос в следующем примере применяет стили к элементам в зависимости от размера ближайшего предка с контекстом изоляции.
Точнее, этот запрос увеличивает размер шрифта заголовка карточки, если контейнер шире `700px`:

```css
/* Стили заголовка карточки по умолчанию */
.card h2 {
  font-size: 1em;
}

/* Если контейнер шире 700px */
@container (width > 700px) {
  .card h2 {
    font-size: 2em;
  }
}
```

Благодаря контейнерным запросам карточку можно повторно использовать в разных частях страницы, не зная заранее, где именно она окажется.
Если контейнер с карточкой уже `700px`, шрифт заголовка будет маленьким, а если карточка находится в контейнере шире `700px` — крупнее.

Подробнее о синтаксисе контейнерных запросов — на странице {{cssxref("@container")}}.

## Именование контекстов изоляции

В предыдущем разделе контейнерный запрос применял стили в зависимости от ближайшего предка с контекстом изоляции.
Контексту изоляции можно дать имя с помощью свойства {{Cssxref("container-name")}}. После этого имя можно использовать в запросе `@container`, чтобы обратиться к конкретному контейнеру.
В следующем примере создаётся контекст изоляции с именем `sidebar`:

```css
.post {
  container-type: inline-size;
  container-name: sidebar;
}
```

Теперь к этому контексту изоляции можно обратиться с помощью @-правила `@container`:

```css
@container sidebar (width > 700px) {
  .card {
    font-size: 2em;
  }
}
```

Подробнее об именовании контекстов изоляции — на странице {{cssxref("container-name")}}.

## Запросы только по имени контейнера

Помимо использования {{cssxref("container-name")}} вместе с [`<container-query>`](/ru/docs/Web/CSS/Reference/At-rules/@container#container-query), к контейнеру можно обратиться только по его имени. Такие **запросы только по имени** (name-only container queries) позволяют выборочно применять стили к элементам в зависимости от того, есть ли у них предок с заданным `container-name`.

Например, возьмём такой HTML:

```html
<div id="container">
  <p>Я в контейнере.</p>
  <p>Я тоже в контейнере.</p>
</div>
<p>Я не в контейнере.</p>
```

Если задать контейнеру имя:

```css
#container {
  container-name: my-container;
}
```

то можно применить стили только к элементам внутри этого контейнера:

```css
@container my-container {
  p {
    background-color: lime;
    font-size: 1.3rem;
    width: 50vw;
    padding: 0.5rem;
    font-family: sans-serif;
  }
}
```

В этом примере заданные стили применятся только к первому и второму элементам {{htmlelement("p")}}, но не к третьему.

## Сокращённый синтаксис контейнера

Контекст изоляции можно объявить короче — с помощью свойства `container`:

```css
.post {
  container: sidebar / inline-size;
}
```

Подробнее об этом свойстве — на странице {{Cssxref("container")}}.

## Единицы длины контейнерных запросов

Применяя стили к потомкам контейнера с помощью запросов к размеру (то есть когда у контейнера {{cssxref("container-type")}} равно `size` или `inline-size`), можно использовать единицы длины контейнерных запросов.
Эти единицы задают длину относительно размеров контейнера запроса.
Компоненты, в которых длины заданы относительно контейнера, легче использовать в разных контейнерах — не приходится пересчитывать конкретные значения длин.

Если подходящего контейнера для запроса нет, единица длины контейнерного запроса по умолчанию равна [малой единице области просмотра](/ru/docs/Web/CSS/Reference/Values/length) по соответствующей оси (`sv*`).

Единицы длины контейнерных запросов:

- `cqw`: 1% ширины контейнера запроса
- `cqh`: 1% высоты контейнера запроса
- `cqi`: 1% строчного размера контейнера запроса
- `cqb`: 1% блочного размера контейнера запроса
- `cqmin`: меньшее из значений `cqi` и `cqb`
- `cqmax`: большее из значений `cqi` и `cqb`

В следующем примере единица `cqi` используется, чтобы задать размер шрифта заголовка в зависимости от строчного размера контейнера:

```css
@container (width > 700px) {
  .card h2 {
    font-size: max(1.5em, 1.23em + 2cqi);
  }
}
```

Подробнее об этих единицах — в справочнике [Единицы длины контейнерных запросов](/ru/docs/Web/CSS/Reference/Values/length).

## Запасные варианты для контейнерных запросов

В браузерах, которые ещё не поддерживают контейнерные запросы, похожего эффекта для карточки из этой статьи можно добиться с помощью {{cssxref("grid")}} и {{cssxref("flex")}}.
В следующем примере объявление {{cssxref("grid-template-columns")}} создаёт двухколоночный макет карточки.

```css
.card {
  display: grid;
  grid-template-columns: 2fr 1fr;
}
```

Если на устройствах с небольшой областью просмотра нужен одноколоночный макет, шаблон сетки можно поменять медиазапросом:

```css
@media (width <= 700px) {
  .card {
    grid-template-columns: 1fr;
  }
}
```
